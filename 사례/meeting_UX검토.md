# meeting 원본 시안 UX 검토 (2026-11-13)

대상: 원본 최종 시안 `design/mockups/v2m-*` 7개 화면 (+ 발표 화면)
방법: 브라우저로 직접 띄워 봄 — 1280(PC) · 400(휴대폰) · 1920(빔) 폭 스크린샷, 홈 Enter 흐름·스튜디오 이어받기 실제 조작, Tab 순서, 누르는 영역 크기·글자 크기 측정. 화면은 `meeting_ux/`.
쓰는 사람: 과장·호선 담당자(작성자), 부장·부서 스텝(부서 편집자), 기획·팀 스텝(기획), 회의 진행자. 쓰는 곳: 사무실 PC, 현장 휴대폰(한 줄·확인), 회의실 빔.

> 이 검토는 shi 0.5.0 `ux-reviewer`(화면을 직접 보고, 작업 흐름을 따라가는 검토)의 시범이다.

## 1. 잘 된 것 — 유지
| 항목 | 근거 |
|---|---|
| 끝내면 다음으로 | 홈에서 한 줄 쓰고 Enter → 저장, 다음 칸으로 포커스, 「되돌리기」 알림. 확인창 없음 |
| 역할별 클릭 수가 적다 | 작성자 한 줄 0 · 초안 2 · 부서 편집자 3 · 기획 3~5 · 회의 진행 안건당 1 (시안 README 표, 홈은 실제 확인) |
| 단축키를 화면 아래에 늘 보여 줌 | 홈 Enter·J/K, 가져오기 1·2·3, 진행 Enter·←/→ |
| 부서 자료 시작 선택을 기억 | 스튜디오 첫 화면 「지난주 이어받기 / 빈 자료」, 다음 주엔 바로 시작 |
| 발표 화면 글자 | 1920 기준 최소 26px (측정 26·30·56·64) |
| 휴대폰 홈 | 400px에서 가로 넘침 없음, 한 줄·저장·변동 없음이 한 손으로 됨 |

## 2. 고칠 것 (우선순위 순)
| # | 화면 | 문제 | 개선 방향 | 크기 |
|---|---|---|---|---|
| 1 | 이슈 | 가장 자주 쓰는 **「이번 주 한 줄」 칸이 기본 줄 4칸 중 하나라 가장 좁다**(≈140px, 글이 잘림). 「호선·다음 일정」도 잘림 | 한 줄을 별도 한 줄 전체 폭으로, 기본 칸은 상태·호선·장비 3칸 | S |
| 2 | 이슈·스튜디오 | **누르는 영역이 작다**: 32px 미만이 이슈 15/32개, 스튜디오 12/14개(체크박스·칩·확대 −/＋·형태 썸네일 라벨 등) | PC 32px·휴대폰 44px 이상. 체크박스는 행 전체 누르기 | S |
| 3 | 이슈 목록 | **제목이 잘림**(「SN2511 발전기 No.2 배기온…」) + 한 행에 신호 5개(상태·매핑 n/5·초안·D-n·! 한 줄 없음) | 제목 두 줄 허용. 행에는 「지금 할 일」 신호 하나만 크게, 나머지는 작게 | M |
| 4 | 스튜디오 | **사실/표현 구분이 작은 점(○/●)뿐**. 사실 칸을 고치면 이슈에 바로 반영되고 작성자에게 알림이 가는데, 눈에 덜 띈다 | 사실 칸에 「이슈에 반영됨 · 작성자 알림」 띠를 고칠 때 바로 보이게, 반영 직후 되돌리기 | S |
| 5 | 스튜디오 | 100% 확대에서 슬라이드 글자가 아주 작다(편집 중 읽기 어려움). 오른쪽 「다른 형태」 변형이 화면 밖으로 반쯤 잘림 | 첫 진입은 「맞춤」, 고른 장은 크게. 변형은 속성 패널 썸네일로만 | M |

| 7 | 홈·전체 | Tab 순서: 첫 할 일 칸까지 **Tab 11번**(메뉴 6 → 역할 3 → A안 보기 → 시안 설명). 첫 입력에 자동 포커스 없음 | 들어오면 첫 빈 칸에 포커스, 「본문으로 건너뛰기」. 시안용 요소(역할 바꾸기·A안 보기·시안 설명)는 앱에서 뺀다 | S |

크기: S 반나절 이내 · M 하루 안팎. 모두 화면 코드만 바꾸고 데이터·API는 그대로.

## 3. 결정 ⑥(흰 사이드바)과의 관계
지금 시안은 네이비 사이드바. ⑥대로 흰 사이드바로 바꾸면 사이드바가 본문과 같은 밝기가 되므로, 지금 메뉴 표시(연한 파랑 + 왼쪽 막대)와 본문 시작 경계(오른쪽 선)가 더 중요해진다 — #7(포커스·건너뛰기)과 같이 본다.

## 4. 확인하지 못한 것
- 실제 사용자(작성자·부서 편집자) 시간 측정 — 팀원 1~2명 써 보기로 확인 (전환 순서 7번 부서 시범 때)
- 다크 테마, 빔프로젝터 실제 밝기, 화면 읽기 프로그램
- 시안은 가상 데이터라 긴 제목·이슈 50건 이상일 때 목록 성능·스크롤

## 5. 적용 위치
전환 작업본의 화면 슬라이스에서 고친다. 1·2·4·7·10(S)은 첫 화면 슬라이스에, 3·5·6(M)은 해당 화면 슬라이스에. 시안 파일은 고치지 않고 작업본 `docs/디자인_규칙.md`에 "시안과 다르게 한 것" 표로 남긴다.
